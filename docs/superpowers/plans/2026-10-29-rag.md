# RAG SDK Implementation Plan

> For agentic workers: use executing-plans for this incremental implementation.
> Maintain this plan as later RAG APIs are agreed; do not create a new plan for
> each pipeline example or implement unapproved stages.

**Goal:** implement the approved standalone content reader, then extend the same
specification and plan for subsequent agreed RAG capabilities.

**Architecture:** `@tessar/rag` owns reading tasks, source acquisition and ordinary
extraction. Core supplies existing JSON validation and error types only. Binary
parsers load lazily. No model calls, persistent registry, agent orchestration or
public transport implementation.

**Tech stack:** Node >=24.22.1, pnpm 11.5.3, strict TypeScript ESM, Vitest;
node-html-markdown, csv-parse, pdfjs-dist, mammoth, read-excel-file.

**Spec:** [RAG design](../specs/2026-10-29-rag-design.md), approved contract
[rag-content-reader-api.md](../../rag-content-reader-api.md).

## Constraints and review focus

- Preserve the single object-input signature, result/cancel methods and bare UUIDs.
- Preserve caller bytes/metadata against mutation; reject mixed source variants.
- Active IDs remain reserved through underlying cancellation cleanup.
- Native failures stay native; cancellation and unsupported content remain explicit.
- Preserve actual source/page information without model inference or caller-metadata pollution.
- Keep package metadata/exports, built consumer and release packaging consistent.
- No edits to core behavior, no version bumps to existing packages, no publish/commit.

### Increment 2 — DocumentSplitter design

- [x] Class name `DocumentSplitter`; selected strategies character, recursive,
  sentence and markdown.
- [x] Separate strategy from measurement; characters/tokens, characters by default.
- [x] Explicit local `Tokenizer.count(text): number` for token units, supplied by
  the application for its destination model; no automatic model lookup or new
  model calls.
- [x] Agree actual algorithms: character windows, recursive boundary refinement,
  sentence-first grouping with fallback, and Markdown structural splitting.
  Record primary implementation references and research in the shared spec.
- [x] Establish implementation checks: preserve content/order/Unicode, handle
  oversized units without infinite recursion, and measure complete token-budget
  candidates rather than adding individual piece counts.
- [x] Accept Content or readonly Content[] and produce chunks carrying text,
  original format/source/metadata; process each Content separately in order.
- [x] Add position {contentIndex,start,end} with UTF-16 slice offsets; retain
  actual source.page separately and independently clone metadata per chunk.
- [x] Require strategy/maxSize; default overlap to 0 and unit to characters;
  require an explicit tokenizer for tokens.
- [x] Return Chunk[] synchronously from chunk(); no asynchronous task lifecycle.
- [x] Agree code-point character measurement, configuration validation, empty
  inputs, boundary-based overlap and hard-limit fallback/error behavior.
- [x] Extend this plan with concrete implementation tasks below.
